# Acceptance matrix (Day 7)

> **Synthetic data.** FitConnect is a fictional company. DDI is an evidence-risk heuristic, not a measure of decision quality. Anything LLM-derived is a replayed fixture or a keyword-rule stub ("stub, not model output"): no live model was called.

Source: PRD section 18 (AC-1 to AC-18), 23.4 (AC-19 to AC-24), 24.6 (AC-25 to AC-29), 25.4 (AC-30 to AC-36), 26.5 (AC-37 to AC-42) and AC-43. Status rules: **PASS** = the whole criterion has linked evidence that was run; **PARTIAL** = some clauses are evidenced and the rest are not met or not measured (named in the notes); **NOT EVIDENCED** = no evidence yet. A criterion is never PASS without linked evidence. Test ids are `file::test` under `tests/` (pytest), Vitest files under `frontend/tests/`, Playwright specs under `frontend/e2e/`. Counts and the run log are in [day-7-implementation-notes.md](day-7-implementation-notes.md).
